# Collector(Agent AI 웹 검색) 테스트 결과 보고서

- 실행일시: 2026-05-10 (KST)
- 실행환경: Docker backend (`backend`), Docker postgres (`stage-one-postgres`)
- 대상 API: `POST /api/v1/collection/jobs`, `GET /api/v1/collection/jobs/:jobId/results`

## 1) 실행 범위
- Query 5개
- planner OFF/ON 각각 1회
- 총 10회 실행

쿼리 목록:
1. icu mortality prediction imbalanced clinical tabular dataset
2. credit card fraud detection highly imbalanced transaction dataset
3. authorship verification korean text dataset
4. electricity load forecasting multivariate time series dataset
5. predictive maintenance anomaly detection sensor dataset

## 3) 핵심 관찰
1. OFF/ON 결과 동일
- 모든 케이스에서 `llmPlanRaw=null`, `llmPlan=null`
- planner ON 상태에서도 LLM plan이 결과에 반영되지 않음

2. source hit 편중
- `connectorStatuses`에서 사실상 `seed-catalog`만 카운트됨
- huggingface/openml/uci/kaggle/serpapi/crossref는 0건

3. 품질 비교 지표 산출 제한
- Planner 효과(관련성/노이즈 감소) 비교를 위한 ON/OFF 차이가 발생하지 않아
- 현재 단계에서는 정량 비교 결론 도출이 불가능

## 4) 환경/설정 점검 이력
적용한 설정:
- `COLLECTION_LLM_PLANNER_ENABLED=true`
- `COLLECTION_LLM_PROVIDER=openai`
- `COLLECTION_LLM_API_KEY=<provided>`
- `COLLECTION_LLM_MODEL=gpt-5-mini`
- `COLLECTION_LLM_API_MODE=responses`

추가 조치:
- `backend/docker-compose.yml`에 `COLLECTION_LLM_*` 환경변수 전달 항목 추가
- backend 컨테이너 재기동 완료

검증 결과:
- 컨테이너 env에는 `COLLECTION_LLM_*` 주입 확인됨
- 그러나 결과 payload의 `llmPlan`은 여전히 null

## 5) 판단
- 완료성(작업 성공률) 기준: PASS (10/10)
- Agent LLM planner 활성 품질 검증 기준: FAIL (ON/OFF 구분 불가)

## 6) PM 공유용 즉시 액션
1. LLM planner 디버그 로그 강화 (최우선)
- `CollectionLlmService.planQueries`에서
  - 호출 여부
  - 응답 status/body preview
  - JSON 파싱 실패 원인
  을 구조화 로그로 남기도록 보강

2. Planner 강제 샘플 엔드포인트/스크립트 추가
- plan raw 응답만 확인하는 smoke endpoint/script 추가
- `llmPlanRaw` 확인이 가능해야 ON/OFF 실험이 성립

3. connector 활성 검증 분리
- `seed-catalog` 외 source가 0건인 이유를 별도 smoke로 분리 진단
- source별 최소 1건 hit 여부를 사전 게이트로 설정

## 7) 결론
- 이번 실행으로 "수집 파이프라인 동작/완료성"은 확인됨.
- 하지만 "Agent AI planner 효과"는 아직 검증 불가 상태.
- 다음 단계는 planner raw/parse 로그 확보 후 ON/OFF 비교를 재수행해야 함.
